# A7 — SDK global-root leak fix (TOW2-324)

- Date: 2026-10-11
- Branch: `fix/sdk-global-root` (worktree `E:/tools/AgentRecall-X-a7`, base main @ db6338a, v3.4.51)
- Worker: A7

## Problem

`new AgentRecall({ root: B })` constructed after `new AgentRecall({ root: A })`
redirected instanceA's subsequent calls to root B, because `setRoot()`/`getRoot()`
in `packages/core/src/types.ts` operate on shared module-level state (`let _root`).
Pinned by `packages/sdk/test/audit-sdk-contract.test.mjs` Case B, previously
`{ todo: true }`.

## Design choice

**Chosen — Option 1: per-call root scoping via `node:async_hooks` AsyncLocalStorage.**

- Core (`packages/core/src/types.ts`): new `const _rootScope = new AsyncLocalStorage<string>()`
  and exported `withRoot(root, fn)` which runs `fn` inside `_rootScope.run(root, ...)`.
  `getRoot()` now resolves `_rootScope.getStore() ?? _root ?? AGENT_RECALL_ROOT ?? ~/.agent-recall`.
  All 74 existing `getRoot()` call sites across 37 core files pick the scoped root up
  automatically — zero churn in core business logic.
- SDK (`packages/sdk/src/agent-recall.ts`): the instance stores `this.root`; a private
  `scoped(fn)` helper wraps EVERY public surface in `withRoot(this.root, fn)` when a root
  option was given (unscoped otherwise): 33 method bodies (17 `withFenced(await ...)`
  pattern, 12 plain delegate pattern, 4 specials: `readAwareness`, `readAwarenessState`,
  `knowledgeRead`, `digestInvalidate`), plus the 5 `palace` getter closures and the 3
  `graph` getter functions (via `scopedFn`).
- Constructor still calls `setRoot(options.root)` — kept deliberately for backward
  compatibility: consumers that construct an SDK instance and then call
  `agent-recall-core` functions DIRECTLY still see that root as the process-global
  default. Instance methods no longer depend on it.
- CLI/MCP server: unchanged and unaffected — they call `setRoot` at startup and never
  enter a scope, so `getRoot()` behaves exactly as before (`getStore()` is undefined
  outside any scope).
- Concurrency-safe by construction: ALS context is bound to each call's async
  continuation chain, so interleaved awaits from different instances each see their
  own root; the scope unwinds on return, throw, and rejection.

**Rejected — Option 2: thread an explicit root/context parameter through core.**
74 `getRoot()` call sites in 37 files; every intermediate signature in storage/paths,
tools-logic, palace, supabase, embeddings would change. Massive, breaking churn for the
same behavior ALS gives for free.

**Rejected — Option 3: SDK calls `setRoot(this.root)` at the top of each method.**
Races under interleaving: `journalCapture` resolves `getRoot()` only AFTER its first
`await resolveProject(...)` suspension (`packages/core/src/tools-logic/journal-capture.ts:34-37`),
so with calls from two instances started before either is awaited, whichever instance
mutates the global root last redirects the other's in-flight write. The new Case C test
is constructed to fail exactly this implementation (all calls started pre-await via
`Promise.all`), and the RED run below shows precisely that failure mode.

### Step 4 — error path (asserted inside Case C, passing)

- Sync throw inside `withRoot(tmpB, ...)`: asserts `getRoot() === tmpB` inside the scope,
  the `boom-sync` error propagates, and `getRoot() === tmpA` (module-level root via
  `setRoot`) immediately after — the scope did not leak.
- Async rejection after an `await` inside the scope (`boom-async`): same assertions;
  scope still resolves correctly after the suspension and unwinds on rejection.
- `process.exit()` inside a scope simply terminates the process; `_rootScope` is
  in-memory per-process state, nothing is persisted, so there is no `finally{}`-skip
  hazard analogous to cleanup-on-exit bugs.

### Step 5 — sync / callback surfaces

- Sync methods `readAwareness()` / `readAwarenessState()` and the sync `palace` /
  `graph` getter functions are wrapped too (ALS `run` works for sync callbacks).
- The SDK exposes no event emitter or detached-callback path (checked all 371 LOC of
  `packages/sdk/src`). ALS propagates through promises/awaits/timers created inside the
  scope; the detached-callback caveat is documented on `withRoot()`'s doc comment.
