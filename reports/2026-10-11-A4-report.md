## Methods (exact functions, modes, estimator)

**Injection size** (`scripts/eval/session-start-size.mjs`, `npm run bench:injection`):
for each project in the store, measure the exact client-visible MCP
`session_start` default payload:

```
text = formatTerse(await sessionStart({ project }))
```

- `sessionStart` — `packages/core/src/tools-logic/session-start.ts:505`
- `formatTerse` — `packages/mcp-server/src/tools/session-start.ts:22`; the tool
  registration defaults are `mode="full"`, `verbose=false` (lines 313–314), and
  the returned `content[0].text` is exactly this string.
- The `ar hook-start` lifecycle hook (`packages/cli/src/index.ts:1571`) calls the
  same `core.sessionStart({project})` and renders a terse text that mirrors
  `formatTerse` field-for-field, so the measured default also represents the
  hook injection. `mode="lite"` / `verbose=true` are not defaults and not measured.
- Estimator: `ceil(chars/4)` — replicates `handoff.ts:275`; core exports no
  estimator function, so bench-lib replicates it (documented in-file). This is
  the same convention behind the 1,489 claim (session-start.ts:174 budget doc).
  No real tokenizer is available without new deps (none allowed). A CJK-adjusted
  sensitivity figure (CJK char = 1 token) is reported per row; identical to
  chars/4 on these all-ASCII fixtures.
- P0 survival: payload P0 count must equal `min(active P0s in store, 10)` —
  the corrections section is `rankCorrections(readP0Corrections(slug), 10)` +
  `applyCorrectionBudget` (P0s always survive the char cap). Violation = exit 1.
- The `auto` project row is printed but excluded from the artifact
  (`resolveProject("auto")` is cwd-dependent → would break determinism).

**Latency** (`scripts/eval/latency.mjs`, `npm run bench:latency`): times the
shipped functions the MCP tools call, with `process.hrtime.bigint()`:

- recall: `smartRecall({query, project, limit:10})` — `smart-recall.ts:907`,
  the function `packages/mcp-server/src/tools/recall.ts` calls, at the tool's
  default `limit=10`. N=200 measured calls after 20 warm-ups, cycling a fixed
  query list (golden-v1: A3's 26-query set `golden-v1.queries.json`; otherwise
  derived deterministically from the store's active correction rules, capped 16).
- session_start: `sessionStart({project})`, N=50 after 5 warm-ups, cycling projects.
- Sequential, single process (the MCP server is single-process too); ms rounded
  to 3 decimals; stats = nearest-rank percentiles + mean, computed from the
  rounded samples; raw `samples_ms` arrays ship in the artifact.

**Isolation (both):** fixture copied to a fresh mkdtemp `AGENT_RECALL_ROOT`
(fresh per project row for injection — `sessionStart` writes telemetry/outcome
records and row N's writes must not bleed into row N+1; one copy per latency run,
where mutation is realistic warm behavior). Network env vars scrubbed before any
core call and re-asserted inside the measured path: `AGENT_RECALL_SUPABASE_URL/KEY`,
`AGENT_RECALL_EMBEDDING_PROVIDER/KEY`, `AGENT_RECALL_EMBEDDINGS`,
`OPENAI_API_KEY`, `VOYAGE_API_KEY`, `ANTHROPIC_API_KEY` (superset of the brief's
four — closes the 2026-08-18 Supabase contamination path). `~/.agent-recall`
never touched (test-proven with a sentinel root). TZ pinned UTC (run-bench §7.3).

## Comparison with the 1,489 / 363 claims

- **1,489 tokens median injection:** fixture numbers are 244 (golden-v1) / 197
  (corpus-v1) — far smaller because both fixtures are thin synthetics (3–4
  projects, a handful of corrections/rooms each) while §C2 measured the owner's
  lived-in store (19 projects, dense corrections, continuity, captures). The
  budget ceiling (~1,500 tokens, session-start.ts:174) is what 1,489 reflects on
  a saturated store; the fixtures don't saturate it. Same estimator, so the
  numbers are commensurable: the claim is plausible for a full store but NOT
  regenerable from this repo — README now says so explicitly.
- **363 ms p95 warm latency:** fixture session_start p95 = 97 ms on this machine
  under load (Linux container: ~15 ms). Different machine, drastically smaller
  store → smaller number. Also honestly noted: the §C2 figure is not regenerable.

## Determinism / non-determinism handling

- Injection sizes on a fixed store are deterministic: fresh temp root per row,
  TZ=UTC, zero Math.random. `--check-determinism` double-runs the full
  measurement and byte-diffs canonicalJson artifacts excluding `generated_utc` —
  added as a CI gate. Known benign exposure: relative-date strings drift across
  calendar days (stable within a job; values never gated across days).
- Latency is marked `non_deterministic:"timing"` in the artifact schema (the
  schema check enforces the marker). CI runs only `--n 20` smoke with the
  built-in shape assertion. `verifyBaseline` recomputes all percentiles from the
  stored `samples_ms` (internal consistency), never compares values across runs.
- `verifyBaseline` extended for `injection-baseline/v1` (recomputes tokens from
  chars, median/p95/max from per_project, survival flags) and
  `latency-baseline/v1` (recomputes stats from samples). Unknown schemas still
  throw; A3's `golden-retrieval/v1` branch intact post-merge.
- Cross-platform find: the store tree hash originally hashed raw bytes and
  drifted between Windows (CRLF autocrlf checkout) and Linux (LF). Fixed:
  CRLF→LF normalization before hashing; verified identical hash
  (`c8bc93ee…` corpus-v1, `6816ea41…` golden-v1) on both platforms.
