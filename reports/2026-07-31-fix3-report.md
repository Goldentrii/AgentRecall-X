# fix3 report — record-aware goal/next-step extraction for raw-archive briefs

Worktree: `/tmp/ar-wave/integration` (branch `wave/integration`), commit `8c68057`
(parent `8c83f4a`). Full diff: 4 files, +300/-69.

## Root cause (confirmed by reading code, not just the defect report)

`resurrect.ts`'s Source-2 loop (raw archive bodies) derived `goalExcerpt`/`title`
via `extractTitleAndGoal()`'s non-markdown fallback branch, which called
`extractFirstProseTextBlock(body)` — a **flat, global regex scan** for
`"text":"..."` over the entire raw body (frontmatter + JSONL), with no
awareness of record type or content-block type. It only excluded matches
whose *own text* contained a `BOILERPLATE_MARKERS` keyword. A `tool_result`
block's nested text (e.g. a `remember()` call's own confirmation echo,
`"Saved → ... Find again: recall(...)"`) contains none of those keywords, so
it could win the scan and be reported as the session's *goal* — exactly the
defect the orchestrator observed.

Separately, `nextSteps` was derived via `extractLinesMatching(content,
NEXT_STEP_LINE_RE, ...)` — run over the **entire raw `content` string**
(frontmatter + all JSONL lines). Since each JSONL line is one physical
"line" and the regex is a plain substring test, any raw JSONL line
containing `next`/`待`/`todo` anywhere inside an embedded blob (attachment
record, tool_use input, tool_result echo) was pushed **verbatim** as a
next-step — reproducing the `{"parentUuid":...}` garbage the orchestrator saw.

Both were the same class of bug fix2 already fixed for
artifacts/Linear-refs (text-level scanning instead of record-aware
scanning) — just not yet extended to these two fields.

## Fix

- **`packages/core/src/storage/extraction.ts`**: promoted
  `session-card.ts`'s private `isSystemText` / `extractFirstUserText` /
  `extractFinal` into shared, exported helpers `isSystemText` /
  `extractFirstUserTextFromRecords` / `extractFinalRecordText` (identical
  logic, identical `minLen` defaults — 10 and 1). These are record- and
  content-block-aware via the existing `textFromContent`/`isBoilerplateRecord`
  primitives, so a `tool_result` block's nested text can never surface
  (it's a sibling block, not a `type:"text"` block in the same array).
- **`packages/core/src/storage/session-card.ts`**: now imports the shared
  helpers instead of its own private copies — pure move, zero behavior
  change (verified: full existing suite green, no assertions touched).
- **`packages/core/src/tools-logic/resurrect.ts`** (Source-2 loop):
  - `goalExcerpt`/`title` now come from `extractFirstUserTextFromRecords(records)`
    — the first real user-authored text, record-parsed — truncated via the
    existing `truncateUtf8Bytes` helper (UTF-8-safe, never a raw `.slice()`
    that could split a surrogate pair). Caps: `RAW_GOAL_BYTE_CAP=200`,
    `RAW_TITLE_BYTE_CAP=160` (matches the pre-existing markdown-heading
    title cap for continuity).
  - `nextSteps` now come from `extractLinesMatching(finalAssistantText, ...)`
    where `finalAssistantText = extractFinalRecordText(records, "assistant")`
    — never raw `content` — so a next-step line can only ever be something
    the assistant itself actually said.
  - When nothing real parses (all boilerplate/system-text/tool_result-only,
    or the line is truncated mid-JSON and `JSON.parse` drops it), the field
    is **omitted** (left unset on the merge entry) rather than falling back
    to a slice of the raw frontmatter+JSONL body — "empty beats garbage."
    The existing entry-level fallback (`title || "(untitled session)"`,
    `goalExcerpt || ""`) already handles the unset case.
  - `parseJsonlLenient(content)` is now called once per file and reused for
    title/goal, artifacts, linearRefs, and next-steps (was parsed twice
    before, once implicitly via the old goal-extraction path's own text scan
    and once explicitly for artifacts/refs).

## Red → green evidence

Two new tests added to `packages/core/test/resurrect.test.mjs`:

1. `"fix3: raw-archive goal is the first REAL user-authored text — a
   tool_result echo ... never wins the goal slot, and next steps come only
   from the final real assistant text"` — synthetic fixture: attachment
   record, then a `tool_result` block echoing remember()-style "Saved →
   ... Next steps recorded internally.", then the real user prompt, then a
   real assistant text with a genuine `Next:` line.
   - **Red** (pre-fix): `goalExcerpt` == the tool_result echo text
     (`"Saved → ~/.agent-recall/... Next steps recorded internally."`).
   - **Green** (post-fix): `goalExcerpt` == the real user prompt exactly;
     `nextSteps` contains the real assistant next-step line and excludes
     the tool_result's "recorded internally" phrase; no field contains
     `{"type"` or `"tool_use_id"` (raw-JSONL-leak guard).

2. `"fix3: an unparseable/boilerplate-only raw archive omits goal/title
   rather than falling back to a raw-body slice — and never crashes"` —
   fixture: one attachment record + one line truncated mid-JSON (no
   closing quote/braces at all, simulating the documented head/tail
   byte-offset truncation).
   - **Red** (pre-fix): `goalExcerpt`/`title` == a ~160-char garbage slice
     of the frontmatter + partial JSON (e.g. `"--- project: ... {\"type\":
     \"attachment\",\"text\":\"SessionStar"`).
   - **Green** (post-fix): `goalExcerpt === ""`, `title === "(untitled
     session)"`, `nextSteps` == `[]`, no crash.

Both confirmed RED against the pre-fix build (`npm run build -w
packages/core` + `node --test test/resurrect.test.mjs`), then confirmed
GREEN after the implementation.
