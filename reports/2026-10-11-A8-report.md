## What changed and why (per line group)

### `.github/workflows/ci.yml`

1. **Top-of-file comment block** — documents what runs where (both lanes run the identical step list), why `windows-latest` exists (owner develops on Windows; bench + tests portable since A2 / `fix/windows-paths`), and the expected state: Windows lane red on exactly one test (recordOutcome RMW race) until `fix/linux-core-tests` (A10) lands, then green.

2. **`strategy.matrix.os: [ubuntu-latest, windows-latest]` + `fail-fast: false` + `runs-on: ${{ matrix.os }}` + job `test-matrix`, `name: test (${{ matrix.os }})`** — the two lanes are independent verdicts; `fail-fast: false` so the known-red Windows lane (pre-A10) can never cancel the ubuntu gate. ubuntu stays THE gate for POSIX-only behavior: 4 POSIX-only tests (3 mcp-server signal tests, 1 symlink) self-skip on win32 with named reasons (verified in this run: core's symlink test skips with `# file symlink creation needs SeCreateSymbolicLinkPrivilege on Windows`), and 1 mode-bit assertion is silently guarded in-test (`packages/core/test/blind-spots.test.mjs:102`), so **no step needs `if: runner.os`**. Verified there is nothing POSIX-only at step level either: all root and per-package npm scripts are pure `node`/`tsc` invocations (the `chmodSync` in mcp-server/cli build runs through Node and is a harmless no-op on NTFS); the 4 regression suites are `node benchmark/*.mjs`.

3. **`timeout-minutes: 10 → 30`** — windows-latest runners are markedly slower than ubuntu and the npm cache may be cold; today's full local pipeline on a Windows dev box is ~8 min cold (dominated by `npm ci` + two 53 s concurrency tests). 30 min is headroom without masking a hang forever.

4. **`defaults.run.shell: bash`** (replaces the two per-step `shell: bash` lines) — every `run:` step now uses bash on both lanes (Git Bash on windows-latest). This is what makes `tee`, pipes, and `2>&1` behave identically; GitHub's explicit-`bash` shell also implies `-o pipefail`, so `npm run lint | tee` still fails the step when lint fails. `setup-node` with `cache: npm` is supported on both OSes.

5. **`env.npm_config_script_shell: bash`** — the one non-obvious bit. On Windows, npm runs *package scripts* through cmd.exe regardless of the step shell. cmd.exe does not glob-expand `test/*.test.mjs` in the per-package test scripts, and the pinned **Node 20** test runner has no built-in glob support (added in Node 21) — so without this, every package's `npm test` would die with "could not find test/*.test.mjs" on windows-latest even though it passes on a local Node 24 box. Forcing npm's script shell to bash (present on both runner images, verified override works via `npm_config_script_shell` env) makes bash expand the glob on both lanes. Verified in effect during the local simulation: npm's failure epilogue shows `command bash -c node --test test/*.test.mjs`.

6. **Artifact name `ci-failure-logs-${{ matrix.os }}-${{ github.sha }}`** — upload-artifact v4 rejects duplicate artifact names, so the two lanes must not collide. Kept `if: failure()` rather than switching to `always()`: the step (SHA-pinned v4.6.2) already existed and uploads both `lint-output.log` and `test-output.log` exactly when they are needed — when the lane fails — which covers the brief's goal (logs visible when core fails); uploading on green runs would only add artifact noise. Everything else in the step (explicit paths only, no globbing, retention 30d) unchanged.

## Fix round (2026-10-12, reviewer verdict: FIX)

Review: `reports/2026-10-11-A8-review.md`. Both findings verified and fixed on `ci/windows-matrix`:

1. **HIGH — branch protection context.** Verified read-only:

   ```
   $ gh api repos/Goldentrii/AgentRecall-X/branches/main/protection/required_status_checks --jq '{strict: .strict, contexts: .contexts}'
   {"contexts":["build-and-test"],"strict":true}
   ```

   The matrix had renamed the reported checks to `build-and-test (<os>)`, so the required context `build-and-test` would never report and every PR would hang on "Expected". Fix: matrix job renamed to `test-matrix` (lanes report as `test (<os>)`) and a dependency-free, non-matrix fan-in job `build-and-test` added — `needs: [test-matrix]`, `if: always()`, single bash `run:` step that fails unless `needs.test-matrix.result == 'success'`. The `always()` + explicit result check is deliberate: a plain `needs:` gate gets reported as SKIPPED when a lane fails or is cancelled, and a skipped check satisfies a required context. `timeout-minutes: 5`, no checkout, no dependencies. **OWNER note:** the alternative is to update main's required contexts to the per-lane names at merge time and drop the fan-in job.

2. **LOW — skip-count wording.** "5 POSIX-only tests self-skip with named reasons" was imprecise: 4 tests self-skip with named reasons (3 mcp-server signal tests, 1 symlink) and 1 mode-bit assertion is silently platform-guarded inside `packages/core/test/blind-spots.test.mjs:102` (the test runs on Windows; only that assertion is skipped). Reworded in the ci.yml top comment, the README note, and this report.
