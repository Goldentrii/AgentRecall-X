## CHECK 2 — the script-shell claim (verified, not folklore)

Claim: on Windows npm runs package scripts via cmd.exe, which doesn't expand `test/*.test.mjs`, and Node 20's test runner has no glob support → every package's `node --test test/*.test.mjs` would fail on windows-latest.

**(a) Node 20 has no `--test` glob support — CONFIRMED empirically + docs.**
Docker `node:20` (v20.20.2, latest v20):
```
node --test "test/*.test.mjs"   → Could not find '/tmp/t/test/*.test.mjs'   (quoted = what node sees from cmd.exe)
node --test test/*.test.mjs     → 2 tests pass                               (bash expanded)
node --test --help | grep -i glob → no glob mention
```
Node v20.x test-runner docs (https://nodejs.org/docs/latest-v20.x/api/test.html): the word "glob" does not appear; CLI args are "explicit file paths and directories" — "one or more paths can be provided as the final argument(s)". (Glob support landed in the v21 line, not v20.) cmd.exe never expands globs (expansion is the app's job on Windows, and Node does not glob argv), so under npm's Windows default shell the literal pattern reaches Node 20 and fails. All four packages use `"test": "node --test test/*.test.mjs"` (`packages/{core,mcp-server,sdk,cli}/package.json`), so the claim covers every package.

**(b) `npm_config_script_shell` is a real npm config env mapping — CONFIRMED.**
npm v10 config docs (https://docs.npmjs.com/cli/v10/using-npm/config):
- script-shell: "Default: '/bin/sh' on POSIX systems, 'cmd.exe' on Windows" — "The shell to use for scripts run with the `npm exec`, `npm run` and `npm init <package-spec>` commands."
- env mapping: "Any environment variables that start with `npm_config_` will be interpreted as a configuration parameter" … "you need to use underscores instead of dashes".
Observed in effect in both the worker's committed log and my reproduction: npm's failure epilogue reads `command bash -c node --test test/*.test.mjs`.

**(c) bash exists on windows-latest — CONFIRMED.**
Note windows-latest now maps to **Windows Server 2025** (not 2022). Its readme (actions/runner-images `Windows2025-Readme.md`) lists "Bash 5.3.15(2)-release", "Git 2.56.0.windows.1", and under Shells: `gitbash.exe | C:\Program Files\Git\bin\bash.exe`. GitHub's `shell: bash` on Windows resolves to Git Bash, and npm's `script-shell: bash` resolves via PATH to the same.
