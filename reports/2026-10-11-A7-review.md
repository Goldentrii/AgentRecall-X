## Findings

- INFO · packages/sdk/src/agent-recall.ts:124 · Constructor still calls `setRoot(options.root)` (deliberate back-compat). Residual: constructing a later rooted instance still moves the GLOBAL root, which affects (a) direct core-API callers and (b) SDK instances constructed WITHOUT a root option (their calls run unscoped and read the global). Both are pre-existing ambient-root semantics, documented in-code, and outside the spec's isolation target (every public method of a rooted instance is scoped). Not blocking · optional follow-up: deprecate constructor `setRoot` in a future major.
- INFO · packages/core/src/types.ts:60-72 · `withRoot()` doc honestly flags the detached-callback caveat (listeners registered outside the scope). SDK exposes no event-emitter surface (verified: packages/sdk/src is only agent-recall.ts + index.ts), so no live hazard.
- LOW · environment, not this change · Multi-child-process tests flake under parallel sibling-agent load: 2 core extras on full run (alignment-log-concurrency, feedback-log-concurrency) and up to 20 CLI spawn-test extras on the loaded run — ALL pass standalone (see numbers below). Failing sets collapse to the baseline exactly. Known class; A7 untouched here.
