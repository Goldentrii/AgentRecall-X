### 1. `assertInsideRoot` (packages/core/src/storage/paths.ts:231) — root now `path.resolve`d before the prefix jail

Attacker-controlled side (`project`/`sid`/`roomSlug` → `resolved` via sanitize + `path.join`) is untouched;
only the trusted root side is canonicalized. Before/after matrix (candidate = resolved string the jail sees):

| case (win32) | root | candidate | OLD | NEW |
|---|---|---|---|---|
| sibling prefix-no-sep | C:/x/root | C:\x\root2\evil | REJECT | REJECT |
| dotdot sibling (join pre-collapses) | C:/x/root | C:\x\root2 | REJECT | REJECT |
| case trick | C:/x/root | C:\x\ROOT\a | REJECT | REJECT |
| deep dotdot escape | C:/x/root | C:\x\root2 | REJECT | REJECT |
| `\\?\` device prefix | C:/x/root | \\?\C:\x\root\a | REJECT | REJECT |
| drive-relative | C:/x/root | \x\root\a | REJECT | REJECT |
| lowercase drive | C:/x/root | c:\x\root\a | REJECT | REJECT |
| mixed-sep candidate | C:/x/root | C:/x/root/projects/a | REJECT | REJECT (callers never produce this; fail-closed) |
| legit child (join output) | C:/x/root | C:\x\root\projects\a | REJECT (bug) | ACCEPT (the fix) |
| candidate == root | C:/x/root | C:\x\root | REJECT (bug) | ACCEPT |
| root trailing slash | C:/x/root/ | (legit child) | REJECT (bug) | ACCEPT |
| root with `..` | C:/x/a/../root | (legit child) | REJECT (bug) | ACCEPT |
| relative root | x/root | x\root\projects\a | REJECT | REJECT |
| UNC root, legit child | //srv/share/root | \\srv\share\root\p\a | REJECT (bug) | ACCEPT |

POSIX matrix: byte-identical OLD vs NEW for every absolute-root case except two operator-controlled root
forms: root containing `..` (OLD erroneously rejected everything → NEW accepts the correct subtree) and a
RELATIVE root (OLD accepted relative resolved paths → NEW rejects everything, fail-closed). Neither is
attacker-reachable; `getRoot()` is absolute in practice. The only POSIX acceptance change requires the
operator to set a weird root, and the relative-root change is a tightening.

End-to-end (built dist, real tmp root): `projectSubPath` with `"../evil"`, `".."`, `"a/../../evil"`,
`"C:\evil"`, `"\\?\C:\evil"`, `"..\..\evil"`, `"a..b"` — every result sanitized INTO `<root>/projects/`,
zero escapes, zero throws-into-wrong-place.

Finding (LOW, comment-only): the new comment at paths.ts:232 says "`resolved` comes out of path.resolve()" —
call sites actually use `path.join` (paths.ts:68, 294, 300, 398). The jail is still sound because join
normalizes `..` and the root is resolved; but the comment misdescribes the invariant. Fix the comment in a
later pass; not gating.

### 2. cwd-allowlist (packages/core/src/storage/cwd-allowlist.ts)

- `normalizePath`: adds slash-canonicalization after realpath. Probed: NO case folding anywhere —
  `c:\users\...` and `C:\Users\...` normalize to DIFFERENT strings (realpathSync preserves input case), so
  on Windows a case-variant cwd can MISS an allowlist match (fail-closed false negative, never a false
  positive). On POSIX case-sensitivity is fully preserved. Trailing-sep stripped; nonexistent paths fall
  back verbatim (slash-canonicalized).
- `startsWith("/")` → `path.isAbsolute`: on POSIX these are identical (no behavior change). On Windows it
  now accepts drive/UNC absolutes (the point). INFO: Windows drive-relative strings like `\foo` also pass
  `isAbsolute`, but a stored entry of that shape can never prefix-match a real normalized cwd
  (`C:/...`), so no widening of matching.
- LOW (theoretical, POSIX): a directory literally named with a backslash (`/a\b`) now normalizes equal to
  `/a/b`, so an allowlist registration for one could match the other. Requires the user to register such a
  dir; inherent to the slash-canonical approach (same tradeoff upstream PR #24 takes). Accepted.

### 3. `classifyPath` (classification.ts:74) — separator-normalize before marker match

Probed: `C:\u\...\corrections\x.json` → personal (OLD returned "project" — the backslash dodge this fix
closes); all markers now hit on both separators; plain project paths still "project". The only behavior
widening is toward MORE protection (personal tier). POSIX literal-backslash filenames can now classify
personal — protective direction. PASS.

### 4. bootstrap realpath jail (`isInsideScanRoots`, bootstrap.ts) — `+ "/"` → `+ path.sep`

POSIX: `path.sep === "/"` → byte-identical, zero change. Windows, probed with a real `mklink /J` junction:

| probe | OLD | NEW |
|---|---|---|
| file genuinely inside root | false (bug — jail rejected everything on Windows) | **true** |
| junction inside root → outside dir, file through it | false | **false** (realpath resolves the junction; escape still blocked) |
| the junction dir itself | false | **false** |

The fix opens only genuinely-inside paths; symlink/junction escape remains blocked. PASS.
