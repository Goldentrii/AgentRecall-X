## FIX list

**FIX 1 — MEDIUM · packages/core/src/storage/filelock.ts:287-289 · blanket win32 EPERM swallows genuine permission errors.**
`tryAcquire` treats EVERY win32 EPERM as "contended, retry". A genuinely read-only/ACL-denied store on Windows now spins to the 5 s no-progress deadline (owner.json never readable → deadline never resets, so it IS bounded at 5 s, not 60 s) and then throws `LockContentionError` claiming a holder — misdiagnosis the function's own pre-existing doc comment warns against. Reliable delete-pending detection on NTFS is not possible (stat on a delete-pending dir itself fails ACCESS_DENIED, so an `existsSync(dir)` narrowing is race-prone), so narrow at the TIMEOUT instead: if the wait expires having NEVER observed an owner record, and an EPERM was being retried, surface the EPERM. Exact patch:

```ts
// tryAcquire: add an optional diagnostics out-param
function tryAcquire(dir: string, diag?: { eperm?: NodeJS.ErrnoException }): (() => void) | null {
  ...
    } else if (code === "EPERM" && process.platform === "win32") {
      if (diag) diag.eperm = err as NodeJS.ErrnoException;
      return null; // delete-pending collision — see doc comment above
    }
  ...
}

// acquireLock: capture + rethrow at timeout when nothing was ever contending
  const diag: { eperm?: NodeJS.ErrnoException } = {};
  for (;;) {
    const release = tryAcquire(dir, diag);
    if (release) return release;
    ...
    if (Date.now() >= deadline || Date.now() >= hardDeadline) {
      // A wait that expires having NEVER seen an owner record, with EPERM
      // being retried as "delete-pending contention", was not contended at
      // all — it is a genuine win32 permission problem. Surface it instead
      // of a fabricated contention claim. (A truly churning lock writes
      // owner.json on every handoff, so some poll in the 5 s window reads
      // one; delete-pending transients last milliseconds, never 5 s.)
      if (lastOwnerKey === null && diag.eperm) throw diag.eperm;
      throw contentionError(name, dir);
    }
```
Behavioral note: `recordOutcome` catches only `LockContentionError`, so on a genuinely broken store this rethrow propagates — correct (environment error, not contention).

## CHECK 1 — filelock progress-aware deadline (highest risk)

Read in full (filelock.ts:334-412). Answers:

- **Can a caller wait 60 s under pathological churn?** Yes, by design: soft deadline (5 s) resets only on observed owner-key change; `MAX_TOTAL_WAIT_MS = 60_000` hard-caps the absolute wait, checked in the same guard as the soft deadline, before the reclaim shortcut — the loop stays provably bounded. LOW observation (no action for A10): hot MCP paths (check.ts:401, smart-recall.ts:450) could now block up to 60 s vs 5 s before, but only under 60 s of CONTINUOUS handoff churn; the common wedged-holder case still fails at 5 s.
- **Could a single holder re-acquiring in a loop count as progress forever?** It counts as progress (acquired_at is `new Date().toISOString()`, ms resolution, so each re-acquire changes the key), but never "forever" — the 60 s cap binds. Same-ms re-acquire by the same pid reads as no-progress, which errs toward the old fail-fast behavior. Correct.
- **Holder dies mid-churn?** Dead-holder reclaim is untouched and still runs every iteration (`tryReclaim`: signal-0 probe + pre-boot rule + rename-aside TOCTOU guard, all byte-identical). A dead holder's frozen key stops resetting the deadline and the corpse is reclaimed on the next poll. Live holders are never stolen from — the never-steal invariant and the live-holder ~5 s timeout test are intact.
- **Contention-skip path?** Intact and documented: `LockContentionError` semantics unchanged; the four catch sites (corrections.ts:1824,1892, check.ts:401, smart-recall.ts:450) unmodified. The 1/day outcome dedup (corrections.ts ~280) reads the lossless ledger and is untouched — A10 never edits corrections.ts.
- **First-observed owner correctly does NOT reset** (`if (lastOwnerKey !== null)`), and an unreadable owner.json (null key) never resets — legacy/crash locks keep the original fixed 5 s. Sound.
