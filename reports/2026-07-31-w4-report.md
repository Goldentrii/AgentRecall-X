## CHALLENGE finding (sync.ts root-fix), reported per instruction

Canonical AR_ROOT resolver in core: `getRoot()` in `packages/core/src/types.ts` —
`_root` (set via `setRoot()`) → `process.env.AGENT_RECALL_ROOT` → fallback
`path.join(os.homedir(), ".agent-recall")`. Every other storage module
(`storage/paths.ts`, `storage/archive-write.ts`, `storage/lifecycle-telemetry.ts`)
already routes through it.

`logSyncError` (sync.ts:80, pre-fix) hardcoded `path.join(os.homedir(), ".agent-recall", "sync-errors.log")`,
bypassing `getRoot()` entirely.

**Callers checked** (`doSync`, `syncCorrectionRecord`, `backfill` in sync.ts; barrel
re-export in index.ts): none depend on the literal hardcoded path — it's a
write-only diagnostic log, never read back by any other code path or test
assertion keyed to that exact location. Safe to fix with no caller impact.

**Reproduction of the pollution confirmed**: `packages/core/test/corrections-sync.test.mjs`
scopes storage via `setRoot(TEST_ROOT)` / `AGENT_RECALL_ROOT` env — **not** a `HOME`
override — and its `syncCorrectionRecord` failure path calls `logSyncError`. Since
the pre-fix code ignored `setRoot()`, that failure wrote straight into the real
user's `~/.agent-recall/sync-errors.log`. The **pre-existing** `sync-errors.test.mjs`
only overrides `process.env.HOME`, which `os.homedir()` already respects on POSIX —
so that test coincidentally passed both before and after the fix and would never
have caught this. Fix: `logSyncError` now resolves via `getRoot()` (same default
fallback, override-aware). New regression test (`sync-errors-root.test.mjs`)
exercises the `setRoot()`-only path — the actual leak vector — and additionally
asserts the real `~/.agent-recall/sync-errors.log` (mtime/size, or non-existence)
is untouched by the call.

## F5 — hook-health.ts

Same shape as `logSyncError` (append + roll@500) plus a derived state file:
- `<root>/hook-health.jsonl` — append-only, rolled to last 500 lines.
- `<root>/hook-health.json` — `{last_failure: {ts,hook,message} | null, failures_24h: number}`,
  rewritten on every `recordHookFailure` call by recomputing from the (rolled) JSONL
  so the derived state can never drift from what's on disk.

Both paths resolve via `getRoot()`. `recordHookFailure` never throws (wrapped in
try/catch); `readHookHealth` never throws, returns a zeroed state on any read/parse
error. CLI catch-block wiring, `ar health`, and the hook-start ⚠️ line are explicitly
out of scope (Wave-2 integrator).

**Date logic vs TODAY**: `failures_24h` excludes rows with `ts > now` — a future-dated
row (clock skew / malformed input) is never counted as "within the last 24h."
Tested directly (`hook-health.test.mjs`: "date logic vs TODAY" case).

## F6 — resurrect.ts

`resurrect({query?, days=14, limit=20}) → ContinuityBrief[]`, `renderResurrectMarkdown(briefs)`.

Sources merged by `(slug, sid)`:
1. `<root>/recent-sessions.jsonl` (optional — depends only on the **documented**
   F2 shape `{ts, sid, slug, title?, next_step?}`, not on W2's code, which doesn't
   exist in this worktree).
2. Every project's `journal/archive/raw/*.md`, filename-date filtered to the `days` window.
3. Every project's `journal/*--card--*.md`.

Card fields win over raw for title/goal (higher-fidelity, already-distilled tier);
artifacts/linearRefs/nextSteps are **unioned** across whichever sources exist for a
session. A card's frontmatter `slug` (when present) overrides the directory it
physically lives under — this is the mechanism that lets a "re-filed" card correct
a misfiled session's identity, per F1's note that confidence+candidates are
recorded specifically so misfiles are "re-fileable later." Tested in isolation.

Ranking: `score = recencyScore` (no query) or `keywordScore + recencyScore`.
`recencyScore = max(0, 1 - ageDays/days)`; a high-confidence keyword hit (title/
goal/linearRefs/artifacts) scores 10, a low-confidence raw-body line-grep hit
scores 3 — directly matching the design's "cards/titles/linearRefs first, raw
line-grep second" instruction.

**Precision extraction (fixture §2's own lesson, applied directly)**: naive
path/Linear-ID regexes over raw text are exactly what misled the incident's own
forensics (hook-boilerplate folder-lint text quoting unrelated files/tickets).
`extractArtifacts` only trusts a `tool_use.input.file_path` JSON field or a
markdown list item as an artifact — never a bare path in prose. `extractLinearRefs`
prefers refs adjacent to a `mcp__linear__*` tool call before falling back to a
plain global scan (kept at lower trust, since this is a recall aid, not a citation
of record). A boilerplate filter (`folder-lint`, `SessionStart:startup`,
`system-reminder`, etc., plus a length cap) excludes hook-noise text blocks from
title/goal extraction on raw-only sessions.

**Bug caught and fixed before it shipped**: my first `linearRefs` regex was
letters-only in the prefix (`[A-Z]{2,6}-\d{1,6}`), which silently fails to match
`TOW2-357` — the design doc's own worked acceptance example, whose team key embeds
a digit. Fixed to `[A-Z][A-Z0-9]{1,5}-\d{1,6}` and verified against the literal
string before writing tests.

**Date logic vs TODAY**: `computeScore` clamps `ageDays` to `>= 0` for a future
timestamp so it can never inflate above the max recency ceiling — but a naive
clamp-to-ceiling still let a clock-skewed future entry *tie or edge out* (via
floating-point luck at exactly the same tick) a genuinely-current entry scored a
few milliseconds later than its own creation. Applied a deliberate 0.99×
penalty to any clamped-future score so it always ranks strictly below a real
"now" entry while still comfortably above older genuine entries. Caught by my
own test suite (a shared "far-future" fixture leaked into the plain
"pure recency ordering" test and flipped the expected #1 result) — fixed, then
reran.
