# Fix2 — resurrect artifact regex + single-source extraction (2026-07-31)

Worktree: `/tmp/ar-wave/integration` @ branch `wave/integration`, base commit `bda11f6`, fix commit `8c83f4a`.
Role: Sonnet fix worker, not the author of the code under fix. Scope: exactly two items from the verifier report (V3 + "additional findings" #3/#5) and the M9 background in `2026-07-31-review-findings.md`.

## Scope (as assigned)

1. `resurrect.ts`'s own `extractArtifacts` regex misses markdown list items where a backtick follows the marker (`` - `~/path` ``) — exactly how real session cards write artifacts.
2. Root cause: `resurrect.ts` reimplements Linear-ref/next-step/artifact extraction separately from `session-card.ts`, so M9's tool_result exclusion and the header exclusion never reached the copies. Class-level fix: extract shared helpers into one module, make both files consume it.

## What was found

Confirmed both bugs empirically before touching code:

- The regex bug is real and exactly as described. `session-card.ts`'s own renderer always wraps artifact paths in backticks when writing the `## Artifacts` section (`sections.push("## Artifacts", ...artifacts.map((p) => \`- \\\`${p}\\\`\`))`), but `resurrect.ts`'s markdown-list-item regex required the character immediately after `- ` to be `~`/`/` directly — a leading backtick broke the match unconditionally. This is why the real-store V3 acceptance query returned `artifacts` missing the 交付物2 path.
- The duplication is real: `resurrect.ts` had its own `extractArtifacts`/`extractLinearRefs`/`extractNextSteps`, parallel to (and lower-rigor than) `session-card.ts`'s M9-fixed versions. Confirmed the M9 leak reproduces through resurrect's path too (see red-test evidence below) — a raw-archive body embedding a `tool_result` block with an unrelated ticket ID leaked into `resurrect()`'s `linearRefs` before the fix.

## Root-cause analysis: two genuinely different input shapes

`resurrect.ts` merges three sources; two matter here:

- **Source 2** (`journal/archive/raw/*.md`): archive-write.ts writes the verbatim transcript JSONL as-is after a frontmatter block — the exact same shape as `session-card.ts`'s `rawHead`/`rawTail`. This CAN be parsed record-by-record.
- **Source 3** (`journal/*--card--*.md`): this is the *already-rendered markdown output* of `session-card.ts`'s own `buildSessionCard()` — plain text/markdown, no record structure survives, and (because it's the output of an already-M9-protected extractor) it never contains a raw `tool_result` JSON blob to exclude in the first place.

So a single flat "one extractor for everything" refactor was wrong for this codebase; the fix creates ONE shared module with both a record-based and a text-based variant of each extractor, and each caller uses the variant that matches its actual input shape.

## Fix shape

New file: `packages/core/src/storage/extraction.ts` — single source for:
- `parseJsonlLenient`, `isBoilerplateRecord`, `textFromContent` (record helpers)
- `extractArtifactPathsFromRecords` / `extractLinearRefsFromRecords` (record-based, M9-protected — excludes `tool_result` blocks)
- `extractArtifactPathsFromText` / `extractLinearRefsFromText` (text-based, for markdown/prose with no record structure)
- `extractLinesMatching` (line-grep with markdown-ATX-heading exclusion — the "header exclusion" the task named)
- Shared regex constants `DECISION_LINE_RE` / `NEXT_STEP_LINE_RE` / the canonical Linear-ref pattern

`session-card.ts`: removed its local copies of all of the above, now imports from `extraction.ts`. **No behavior change** — all 12 of its existing tests pass unchanged, byte-for-byte.

`resurrect.ts`:
- Source 2 now parses raw archive bodies via `parseJsonlLenient` and uses the record-based, M9-protected extractors — genuinely closes the tool_result leak for this source (not just "same rigor," strictly more correct than before).
- Source 3 uses the text-based extractors, with the regex bug fixed (see below) and the markdown-heading exclusion applied to next-step matching.
- Dropped its own bespoke two-tier "near mcp__linear__ tool call, then global scan" Linear-ref logic entirely — the shared record-based extractor (scans ALL tool_use inputs, not just mcp__linear__ ones) is a strict superset.
- `resurrect()` now inherits `session-card.ts`'s semantics on the shared Linear-ref pattern (unbounded `\d+` instead of resurrect's old `\d{1,6}` cap) — negligible practical difference, explicitly sanctioned by the task ("resurrect inherits them").

### Regex fix detail (with a self-caught regression)

First draft of the fix folded the "tolerate backtick/bold" requirement into the captured path's character class (`[^\s\`*_]+`), which — I caught this before it reached the report — **corrupted real CJK filenames containing literal underscores** (`交付物2_MCP原型_V14.html` got truncated to `交付物2`). Fixed by matching the opening marker as a literal alternation (`` (?:`|\*\*|__)? ``) outside the capture group, keeping the capture char class exactly as before (`[^\s\`]+`, excludes only whitespace/backtick), and stripping any trailing closing marker in a separate bounded cleanup step after the match. Verified against backtick, bold, and plain-unwrapped paths, plus the exact CJK-underscore path from the real fixture.
