## Design decisions (flagged per CHALLENGE instruction)

1. **"AR_ROOT env" terminology**: the codebase has no literal `AR_ROOT` env var — root resolution is `getRoot()` (`AGENT_RECALL_ROOT` env / `setRoot()` override) in `packages/core/src/types.ts`. `recency-index.ts` resolves its path via `getRoot()`, same as every other storage module (`paths.ts`), so it is fully testable/overridable exactly like the rest of the store. Read this as what the design doc meant by "AR_ROOT-aware."
2. **No slug filtering in `readRecentSessions`**: the design doc says "top-3 recent cross-slug entries" and "cross-project by design" — I read this as "the ledger itself isn't project-scoped" (unlike journal/palace dirs), not as "filter out the current project's own entries." I implemented **pure top-3 by recency, unfiltered by the calling project's slug**. This matches the literal acceptance criterion ("session_start surfaces entry written by another slug") but means if the 3 most recent entries all happen to belong to the *current* project, the continuity section will (harmlessly) duplicate what `resume`/`recent.today` already show. No filtering logic was specified anywhere in F2, so I did not invent one — flagging this for the Wave-2 integrator/reviewer in case exclusion-of-current-slug is actually wanted.
3. **SECTION_CHAR_LIMITS integration**: added `continuity_title` (160), `continuity_next_step` (160), `continuity_total` (500 JSON chars) following the exact existing pattern (per-field raw cap at construction time, then a total-JSON budget loop identical in shape to `insightsBudgeted`/`roomsBudgeted`/`capturesBudgeted`). No conflict with the existing budget system — it composes cleanly.
4. **`appendRecentSession` has no caller yet** (by design — Wave 2's job is the CLI hook-end write site). All of my tests call `appendRecentSession` directly to seed fixtures before exercising the read side.
5. **`formatTerse`/`formatLite` exported**: neither was exported before (matches `recall.ts`'s un-exported `formatResults`), but F2 explicitly requires testing the terse "⏪ Continuity" top section, so I exported both (pure functions, no I/O) rather than standing up a full MCP stdio round-trip test (the repo does have that pattern elsewhere — `project-board-text.test.mjs` — but a pure unit test is faster/less flaky and sufficient here).
